# 2026-11-12: kickoff

Cloud session. First session on this project.

## How it started

The user shared a photo of a handwritten wishlist and asked how to approach
the animation pipeline. The list, as written:

- animation pipeline with Moho and Maya/RenderMan
- automated scripts and YouTube channels; monetized, organic looking, TTS
- specific themes, reports, trend analysis
- vectorized assets, reusable and remixable
- a separate email and account, with a question mark
- rigs, meshes
- "HyperRigs": rigs with so many switch layers and controllers a human could
  not possibly animate them
- an arrow from the pipeline to "custom 3D shaders for animation"

A lower section of the page about hardware and laptops belongs to another
project and was set aside at her request.

She plans to have assistants rig and animate. Assets will be hers or CC0, and
human-made. She asked for a skill file and a way for several assistant
instances to work together, and said findings could go in this repo, which was
picked only as a place to run a cloud session.

## What was learned

**Moho projects are editable data.** The plan depended on whether an assistant
could rig and animate without the Moho UI. A real project file answered it:
ZIP, one JSON document, every property a keyframe list. A tool now reads it,
names the controls and writes keys, and an untouched file re-saves byte for
byte. This was the most useful hour of the session, and it came from finding a
committed sample in an open-source Godot importer after a first sample turned
out to be an unreachable LFS pointer.

**The byte-identical check is worth keeping.** Python's JSON writer emits
`-8e-05` where Moho writes `-0.00008`. Probably harmless, but matching Moho
exactly means any difference in an output file is one the tool intended. That
makes mistakes visible.

**The voice leg runs anywhere.** Kokoro and Rhubarb both worked in the
sandbox, and the generated switch data matches Rhubarb's own export exactly.

**The 3D tools cannot be used as licensed.** Educational Maya and
non-commercial RenderMan do not cover a monetized channel. Raised with the
user as a decision, not settled for her. (This was wrong about her setup; see
the second follow-up below.)

## Positions taken, and why

- **"Organic looking" was reframed as "authored".** The monetization rules
  target template sameness across a channel, not AI assistance. Hiding
  automation is the harder and riskier goal; being original is the one the
  rules reward. She may disagree; it is her call.
- **HyperRigs should keep a human handle.** The concept holds up: control
  count is not a cost for a model. But a rig she cannot adjust by hand takes
  away her veto. About ten master dials on top.
- **The repo is the coordination layer.** The instances run on different
  surfaces at different times, so anything that needs them alive together
  would not work. Tickets, handoff entries and this journal do.
- **No lane-specific agent definitions yet.** Lanes are described in the
  collaboration reference. Turning one into an agent file is worth doing after
  it has been run by hand a few times, so the definition records what worked.

## Working preferences that bear on the project

- Free and open-source first; look for an existing tool before writing one.
- She wants a collaborator who argues a position, not agreement.
- Feedback as reasoning first, suggestion second.
- She is learning Python and C++, so tools should be readable enough to learn
  from.

## Follow-up the same day: scope of 3D, and what "organic" means

After reading the first pass, the user clarified two things.

**3D is a side dish.** Maya and 3D would not be there all the time; at most
small assets rendered with shaders applied. She wants the show mostly Moho so
it stays looking organic and 2D. The first pass had treated 3D as a lane of
its own with sets, plates and camera matching. That was more than she asked
for. The 3D reference is now written around one job: render a small asset,
bring it into Moho as an image or as a switch layer of angles.

**"Organic" was misread.** The first pass took "organic looking" on the
wishlist to mean making automated output pass as hand-made, and argued
against it. She means the aesthetic: 2D, hand-made in feel. That is a style
goal and a sound one. The point about YouTube's rules still stands, but as a
separate matter (sameness across a channel), not as a correction of her goal.
Lesson for later sessions: when a word on the wishlist can be read as either
a look or a tactic, ask which before arguing with it.

The license issue did not go away, since one prop in a monetized video is
still commercial use, but it dropped from "decide before building" to "decide
when the first asset comes up".

## Second follow-up: licenses and what "reusable" means

Two more corrections from the user.

**Her tools are not student licenses.** The first pass reasoned "student,
therefore educational licenses" and built a ticket, a README section and a
recommendation to move to Blender on top of it. She had never said that. Her
own machine has paid licenses; the educational ones are the school's, plus a
student account she rarely uses at home. The license material is now about
which account the work is done under, and T-0004 is closed. The general facts
about license types were right; applying them to her was not.

**Reuse was never the worry.** She read the earlier cautions about sameness
and provenance as concern over reusable assets, and explained what she meant:
an environment used a couple of times, props that recur, tileable flower and
moss textures so greenery stays fresh without extra effort. That is ordinary
production economy and has nothing to do with the YouTube rule, which is
about interchangeable videos. The wishlist item "vectorized assets, reusable,
remixable" had been under-served; there is now an assets reference covering
the library layout, reference layers, tileable textures and a tested
seam-check command.

Three assumptions in one day, all of the same kind: filling a gap in what she
said with the most cautious reading and then arguing with it. They are listed
in `pipeline/README.md` so later sessions do not repeat them. The better move
each time would have been one short question.

## What is unproven

Everything that needs Moho or Maya open. T-0001 is the one that matters most:
if Moho 14 rejects a tool-edited file, the animation lane changes shape and
Lua scripting inside Moho becomes the route instead.

The skill has not been through an evaluation pass with test prompts.
